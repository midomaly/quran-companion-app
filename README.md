## Noor Al-Islam — The Complete Qur'an & Muslim Companion

**You read the Qur'an** — all 114 surahs, all 6,236 ayahs, in Uthmani script
with your choice of 8 verified translations, recitation audio, bookmarks,
search and offline reading — and the app covers the rest of a Muslim's day: prayer
times with alarms, Qibla, tasbih, duas, hadith and a Hijri calendar. No
account is ever required to read.

### Features

- **Splash + branding**: emerald/gold identity, crescent mark, Islamic
  geometric pattern, light & dark mode.
- **Home dashboard**: "As-salamu alaikum" greeting, Gregorian + Hijri (Umm
  al-Qura) dates with local time, Continue Reading (persisted last-read
  position), Verse of the Day (real ayah from the source, changes daily),
  quick links into the Qur'an and every companion section.
- **Interface in 5 languages**: English, العربية (full RTL), Français,
  Hausa and Yorùbá — chosen in Settings. The UI language is independent of
  the Qur'an translation: no unverified translation is ever substituted.
- **Qur'an hub** (`/quran`): all 114 surahs (filterable), all 30 juz,
  full-text search (English translation + Arabic Uthmani), bookmarks tab,
  and a **Plans** tab — Khatmah planner with 7/15/30/90-day targets, juz
  logging and honest behind/ahead pace commentary.
- **Reader** (`/quran/:surahId`): Uthmani text + your chosen translation,
  ornamental basmala line, adjustable Arabic font size, ayah jump,
  bookmark/copy/share/note per ayah, **personal ayah notes** (device-local),
  **per-ayah tafsir** (Ibn Kathir Abridged in English, Tafsir al-Muyassar
  in Arabic — labelled scholarly commentary, fetched on demand),
  **loop-range playback** for memorisation (from–to ayahs × 3/5/10/∞),
  automatic last-read tracking, reading progress bar, verse-by-verse audio
  (7 reciters, play/pause/prev/next/continuous/repeat/speed, lock-screen
  media controls).
- **8 verified translation editions**: Saheeh, Pickthall, Yusuf Ali,
  Hilali & Khan, Français (Hamidullah), Hausa (Gumi), Indonesia (Kemenag)
  and Türkçe (Diyanet) — every identifier was verified live against the
  source before being listed. The choice syncs to your account and caches
  per edition for offline reading.
- **Prayer times** (`/prayer`): an offline astronomical engine (PrayTimes-
  style solar position math) computes Fajr→Isha for your location with 9
  calculation methods, Madhab/Asr choice and high-latitude fallback;
  countdown to the next prayer, notification permission, and per-prayer
  adhān alarms (reminder host runs app-wide).
- **Prayer Alarm & Adhan Settings** (`/alarms`): the alarm control centre —
  per-prayer enable, timing (at prayer time / 5 / 10 / 15 minutes before), a
  sound library of **real recordings** (two full adhans + the Fajr adhan with
  its extra wording, from archive.org's Public-Domain “Adhan Recordings from
  Doha, Qatar”), previewed with play/pause/stop before selecting, plus two
  synthesized offline tones, silent mode, alarm volume, quiet hours, test
  alarm, notification & vibration control and restore-defaults. The home
  screen shows the next prayer with a live countdown and its alarm status.
  Nothing fake stands in for the adhan: a recording that fails to load is
  shown as unavailable, never as ringing.
- **Notification center** (`/reminders`): personal reminders with weekday
  schedules, quiet hours and snooze — same honest in-app engine.
- **Qibla** (`/qibla`): great-circle bearing and distance to the Kaaba from
  your prayer location, live device-compass with permission/denied/no-
  sensor fallbacks, magnetic-interference warning with figure-eight
  recalibration guidance, city quick-picks.
- **Tasbih** (`/tasbih`): tap-to-count with haptics and a completion chime
  (both toggleable), target rings, **custom dhikr phrases and targets**,
  **undo** (button + Ctrl+Z), reset confirmation, auto-logged **session
  history** with today/yesterday/lifetime stats and a 7-day chart.
- **Duas** (`/duas`): curated authentic supplications (morning/evening,
  prayer, travel, food, distress…) with Arabic, transliteration and
  translation — **searchable**, with **favorites**, per-dua **repeat
  counters** (1/3/7/33/100) and **share**.
- **Hadith** (`/hadith`): attributed hadith collection including the Forty of
  an-Nawawi, with narrator grading.
- **Hijri calendar** (`/calendar`): **month/week/day views** with dual Hijri/
  Gregorian dates (Umm al-Qura via Intl), **±2-day manual adjustment**
  applied app-wide, Islamic events (Ramadan, Eids, ʿĀshūrāʾ, Laylat
  al-Qadr…) **plus your own events with optional reminders**, a
  **Hijri↔Gregorian converter**, share-a-day and a printable month.
- **Learning center** (`/learn`): guides (pillars, wuḍūʾ, ṣalāh), a Seerah
  timeline and a short quiz — educational material, kept separate from
  Qur'an and hadith, with a "practice questions belong with a qualified
  scholar" notice.
- **Ramadan & zakat** (`/ramadhan`): Ramadan tools and a zakāt calculator
  (pure, unit-tested math).
- **Worship tracker** (`/tracker`): a gentle daily checklist (prayers, Qur'an,
  adhkar, fasting, charity, memorization) with streaks and a 7-day view.
- **Mosque finder** (`/mosques`): real nearby masjids from OpenStreetMap
  (Overpass mirrors) with distances, addresses and directions — nothing
  invented, with graceful fallback when the service is unreachable.
- **Offline & downloads** (`/downloads`): download/remove per-surah text,
  cache inventory with sizes, storage usage, network + sync status, clear-
  all with confirmation. Every surah read once is cached on-device; an
  offline banner and graceful error states cover the rest.
- **Accounts & sync**: sign in (`/auth`) and bookmarks, last-read position,
  settings (incl. translation edition) and recent searches merge across
  devices via Convex — while everything continues to work fully offline
  without an account.
- **Settings**: theme, language, Arabic size, translation edition, reciter,
  source attribution, offline-cache management. All preferences persist
  locally.

### Android APK (automated CI build)

Pushing to `main`/`master` runs `.github/workflows/android-apk.yml` (it can
also be started by hand: Actions → **Build Android APK** → Run workflow), which:

1. typechecks, runs `bun test` and lints;
2. builds the site under the repo sub-path (SPA `404.html` fallback,
   sub-path-scoped manifest) and deploys it to **GitHub Pages** — the web
   app's permanent URL: `https://<owner>.github.io/<repo>/`;
3. builds a signed Android **Trusted Web Activity** APK with
   [Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap) against the
   deployed site and attaches it to a GitHub release.

**APK download link** (always the newest build) — a URL *template*: replace
`<owner>` with your GitHub username or organization and `<repo>` with the
repository name. It resolves only after the project is pushed to GitHub and
the workflow has produced its first release.

```
https://<owner>.github.io/<repo>/            <- the deployed web app
https://github.com/<owner>/<repo>/releases/latest/download/app-release-signed.apk   <- the APK
```

Concrete example for GitHub user `midomaly`, repo `quran-companion-app`:

```
https://midomaly.github.io/quran-companion-app/            <- the deployed web app
https://github.com/midomaly/quran-companion-app/releases/latest/download/app-release-signed.apk   <- the APK
```

(Easier to browse: `https://github.com/<owner>/<repo>/releases/latest` lists
the assets — tap `app-release-signed.apk`.)

One-time setup (repository → Settings):

1. **Pages → Source: "GitHub Actions"** — required, or the deploy step fails.
2. Optional secrets (Settings → Secrets and variables → Actions). The
   pipeline works with none of them: it generates a throwaway signing key
   (password `noor-android`) and posts a warning telling you to archive it.

| Secret | Purpose |
| --- | --- |
| `KEYSTORE_BASE64` | Your own release key: base64 of `android.keystore`. **Archive it** — without it later builds generate a fresh key and won't install as updates over earlier APKs. |
| `ANDROID_KEYSTORE_PASSWORD` | Your keystore's password (default `noor-android`; required whenever you supply your own key) |
| `ANDROID_KEY_PASSWORD` | Password for key alias `android` (default `noor-android`) |

To use your own key, create the keystore once (keep it safe — losing it
means losing update signing), then store all three secrets:

```bash
keytool -genkeypair -v \
  -keystore android.keystore -alias android \
  -keyalg RSA -keysize 2048 -validity 10000
base64 -w0 android.keystore   # GNU; macOS: base64 -i android.keystore
```

The committed `android/twa-manifest.template.json` keeps the build fully
non-interactive (package id `com.freebuff.nooralislam`); CI fills in the
owner/repo, the signing certificate fingerprint and the keystore at build
time. If generated, `assetlinks.json` ships with each release — host it at
`/.well-known/assetlinks.json` on the Pages site to hide the browser bar in
the installed app.

### Adhan alarms: platform limits and the native Android path

Alarms are driven by the in-app scheduler (`duePrayerAlarms`, executed by
`PrayerReminderHost` on a 20-second tick plus a visibility check, with a
3-minute grace window and once-per-day dedupe). This is the honest capability
matrix — the settings screen states it in plain language too:

| Situation | What happens |
| --- |
| App open (browser tab or installed TWA) | Adhan/tone, vibration, notification and toast fire on time, once per prayer per day. |
| Tab frozen by Android battery optimization | Timers stop. Set the app to **Unrestricted** battery (Settings → Apps → Noor Al-Islam → Battery). |
| App closed or force-stopped | Nothing can ring. Browsers cannot wake a closed tab without a push server, and a web-push notification cannot carry a full-length custom adhan sound on Android. The app never pretends otherwise. |
| Device restart | Alarms re-arm automatically the next time the app opens — they are recomputed from the prayer engine, never persisted as stale one-shots. |

For **exact background alarms** (the adhan rings at Fajr with the app closed)
the supported route is native Android. The repo already produces a signed TWA
APK in CI; the missing pieces are:

1. Manifest permissions: `USE_EXACT_ALARM` (alarm-clock use case),
   `POST_NOTIFICATIONS`, and `FOREGROUND_SERVICE_MEDIA_PLAYBACK` if a
   foreground service plays the adhan.
2. `AlarmManager.setExactAndAllowWhileIdle()` per prayer, re-armed from a
   `BootReceiver` on `ACTION_BOOT_COMPLETED` after a restart. Use the
   prayer+date as the `PendingIntent` request code, and call
   `AlarmManager.cancel` whenever a toggle/lead changes — the web settings
   screen already funnels every change through one place, so a thin JS
   bridge (`window.NoorAndroid?.scheduleAlarm(...)`, feature-detected, absent
   = web behaviour) keeps both layers consistent.
3. A full-screen-intent notification (`Notification.fullScreenIntent`) at
   prayer time with a `MediaPlayer` playing the same adhan recording bundled
   in `res/raw/` so it works fully offline.
4. Keep this repo as the web layer and add a Kotlin wrapper that loads the
   Pages URL in a `WebView` and implements the bridge above; Bubblewrap
   supports custom code via `bubblewrap merge`.

Until that wrapper exists, the TWA build inherits the table above: honest
in-app alarms while open, no background ringing.

## Protected Routes

The starter `/dashboard` route is protected with `RequireAuth`. Extend that page
for the product's authenticated experience, and reuse `RequireAuth` when adding
another protected route — do NOT hand-roll a redirect to `/auth`, since landing
on a bare sign-in form with no explanation of what was blocked is confusing.

`RequireAuth` states the block on the page the visitor asked for and sends them
to `/auth?returnTo=<current route>` when they choose to sign in, so they come
back to it. Pass `title` and `description` to say what the page is:

```tsx
<Route
  path="/dashboard"
  element={
    <RequireAuth
      title="Sign in to view your dashboard"
      description="Your projects and settings live here."
    >
      <Dashboard />
    </RequireAuth>
  }
/>
```

Pass `redirectImmediately` for a route where bouncing straight to `/auth` really
is better.

# Using the Convex backend

You will be implementing the convex backend. Follow your knowledge of convex and the documentation to implement the backend.

## The Convex Schema

You must correctly follow the convex schema implementation.

The schema is defined in `src/convex/schema.ts`.

Do not include the `_id` and `_creationTime` fields in your queries (it is included by default for each table).
Do not index `_creationTime` as it is indexed for you. Never have duplicate indexes.


## Convex Actions: Using CRUD operations

When running anything that involves external connections, you must use a convex action with "use node" at the top of the file.

You cannot have queries or mutations in the same file as a "use node" action file. Thus, you must use pre-built queries and mutations in other files.

You can also use the pre-installed internal crud functions for the database:

```ts
// in convex/users.ts
import { crud } from "convex-helpers/server/crud";
import schema from "./schema.ts";

export const { create, read, update, destroy } = crud(schema, "users");

// in some file, in an action:
const user = await ctx.runQuery(internal.users.read, { id: userId });

await ctx.runMutation(internal.users.update, {
  id: userId,
  patch: {
    status: "inactive",
  },
});
```


## Common Convex Mistakes To Avoid

When using convex, make sure:
- Document IDs are referenced as `_id` field, not `id`.
- Document ID types are referenced as `Id<"TableName">`, not `string`.
- Document object types are referenced as `Doc<"TableName">`.
- Keep schemaValidation to false in the schema file.
- You must correctly type your code so that it passes the type checker.
- You must handle null / undefined cases of your convex queries for both frontend and backend, or else it will throw an error that your data could be null or undefined.
- Always use the `@/folder` path, with `@/convex/folder/file.ts` syntax for importing convex files.
- This includes importing generated files like `@/convex/_generated/server`, `@/convex/_generated/api`
- Remember to import functions like useQuery, useMutation, useAction, etc. from `convex/react`
- NEVER have return type validators.
